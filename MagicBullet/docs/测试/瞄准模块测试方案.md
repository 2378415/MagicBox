## 5. 台架协议用例（PC + 盒子，已执行）

| 编号 | 用例 | 步骤 | 预期/实测 |
|---|---|---|---|
| PT-01 | 版本与连通 | `.km.version()` | `km.MAKCU` ✔ |
| PT-02 | AIM 单发位移 | `AIM(300,0)` max_ms=10 | 光标位移≈300 逻辑 px ✔ |
| PT-03 | AIM_RESET | 打 30 发后 `0x40` → `0x3D` | `rounds 30 → 0`、`result 1 → 0` ✔ |
| PT-04 | 按键优先级 | 1 kHz AIM + 按键风暴，读 `0x3E` | `btn_in = btn_sent`（128/128），`wait_max ≈ 9–221 µs`，`overflow 0` ✔ |
| PT-05 | 按键回环审计 | 6 s 重载下读 `0x3F` | `in_chg == out_chg`、`extra = 0` ✔ |
| PT-06 | 事件通道 | `0x3B` 连续两次 | 推模式下 `seq/overflow` 不增长 ✔ |
| PT-07 | 事件环重置 | `0x41` → `0x3B` | `seq=0 overflow=0` ✔ |
| PT-08 | 重连后 SUMV 正常 | 断开→连接→发送 SUMV ×2 | 无「写失败」，PING ≤1 ms ✔ |
| PT-11 | SUMV 报告字节自检 | 发 SUMV 后读 `0x42 LAST_HID` | 回包 `len=7`、首字节（按钮）=0x00；实测 `00 00 00 FF FF 00 00`，光标 Δ=198 px、期间左键按下 0 次 |\n| PT-10 | 注入不受开机时长影响 | 刷机后立即发 SUMV，再等 40 min 重发 | 两次光标都移动（回归「32 位时间相减恒为正 → 全体注入被丢弃」缺陷；2026-11-11 修复并实测 Δ=197 逻辑 px） |

### 6.1 真机判定方式

- **热键类**：以 `cache/control.log` 为准（每次边沿 / 切换 / 被吞 / 补发都落盘）；
- **瞄准类**：以 `0x3D AIM_STATE` 的 `rounds/dead_hits` 增长 + 状态行残差为准；
- **按键类**：以 `0x3E/0x3F` 的 `in==sent`、`extra==0` 为准。

```powershell
adb -s <IP:PORT> shell "run-as com.magicbullet.capture cat cache/control.log" > control.log
```

## 8. 已知限制与风险

| 项 | 说明 | 处理 |
|---|---|---|
| 游戏灵敏度未知 | 桌面 px/count 不代表游戏内响应 | 由自校准增益在线吸收 |
| AIM 有 1.67% 侧向弧 | `SUMV_CURVE_AIM=60` | 方案 D（严格直线）已评估未实施 |
| 无线鼠标成簇节拍 | 盒子与固件均不丢帧（`extra=0` 佐证） | 硬件建议：2.4G 接收器直插盒子 |
| 校准页依赖采集卡 | 无卡时只提示「没抓到帧」，仍可拖框 | 属预期降级 |
| 自学习需要样本 | <5 样本或 3 s 无新样本 → 回落到手填值 | 已实现并有单测覆盖 |
