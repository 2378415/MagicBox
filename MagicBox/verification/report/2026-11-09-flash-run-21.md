# 上机记录：2026-11-09 第二十一批（**端到端透传打通**）

> 真实鼠标 → 右片（host）→ UART1 → 左片（device）→ PC 光标。实测 **2,256 帧进、2,256 帧出、0 失败**。

## 1. 结论

| 项 | 结果 |
|---|---|
| 右片持有鼠标 | 稳定 `state=00`（`0xA0` 回 `00`） |
| 右片转发 | `hid = 2256`（真实 `0xA2`，5 字节报告） |
| 左片注入 | `injected = 2256` |
| 主机接受 | `hs = 2256 ok / 5 busy / 0 failed` → **一对一，零丢失** |
| 光标 | 跟手（`w=1` 移动两个方向均实测位移） |

## 2. 真凶：报告字节顺序错误（一个 bug 卡了三轮）

`makcu_report_t` 的字段顺序是 `{dx, dy, wheel, buttons}`，旧代码把这个结构体**原样**当作 HID 报告发出：

| 报告字节 | HID 描述符要求 | 旧代码实际发的 |
|---|---|---|
| 0 | buttons | **dx** |
| 1 | x | **dy** |
| 2 | y | **wheel** |
| 3 | wheel | **buttons** |

主机收到的永远是错位数据 → 光标不动，但设备健康、传输完成、`hs ok` 有增长。
这就是"发出去了却没反应"的全部原因。

修正（`makcu_hiddev_report()`）：按描述符顺序显式组包
`{buttons, dx, dy, wheel}`（克隆态 4 字节、无 Report ID 前缀；内置描述符态 5 字节、ID=2）。

## 3. 同时解决的两个真问题

### 3.1 TinyUSB 端点 claim 泄漏（成功率 0.8% → 100%）

`tud_hid_n_report()` 先 `usbd_edpt_claim()` 再 `usbd_edpt_xfer()`，后者内部的
`usbd_edpt_ready()` 返回 false 时**不释放 claim**；`tud_hid_busy()` 仍是 0，所以
`mx.hs` 的 `busy` 计数一直是 0，极具误导性。

修法：不再从链路任务/鼠标任务抢发，改成在 **`tud_hid_report_complete_cb()`**
（端点刚被释放的那一刻）里补发下一条累积位移（`makcu_mouse_pump()`）。
实测 `failed` 从 9,399 降到 **0**。

### 3.2 Windows 选择性挂起把 IN 轮询拉长

关掉前：单条报告完成要上百毫秒，1 kHz 灌入必然堆积。
已全局（`powercfg` USB 选择性挂起 = 禁用）与设备级
（`USB\VID_046D&PID_C077\...\Device Parameters`：`EnhancedPowerManagementEnabled=0`、
`SelectiveSuspendEnabled=0`）关闭。

## 5. 关键机理备忘（逆向所得，已实测验证）

- 右片**只在 `*DAT_42000d48 != 0` 时**把 `0xA2` 入队；该标志只由**左片发 `0xA3`**置位
  （`frame_a3_flag`，`0x4200FAE0`），设备掉线时由 `frame_build_ep0(0)` 清 0。
  → 左片必须主动宣告，且要周期性补发。
- `0xA2` 载荷 = `[ep, session, len, 0, data…]`，真实鼠标 `len=5`
  （`buttons, dx, dy, wheel, pan`）。
- 片间链路：UART1、5 Mbaud、左 TX=GPIO2/RX=GPIO1、右 TX=GPIO1/RX=GPIO2。

## 6b. 回归与可测试性（本轮新增）

新架构 + 真实流量让三个老用例失去确定性，处理方式不是放宽断言，而是把台架变确定：

| 用例 | 失败原因 | 处理 |
|---|---|---|
| `test_hid_frame_injects_a_report` | 真实鼠标已把会话 id 定成 `0x81`，用例里的 `0x22` 被判不匹配 | 新增 `mx.ss <hex>`（强制会话 id，`00` 回自动），用例改为先钉 `0x22` |
| `test_hid_frame_session_mismatch_is_dropped` | 同上 | 同上 |
| `test_clone_survives_a_move` | 真实 `0xA2` 持续进 `mx.rq` 轨迹，`090700` 被挤出窗口 | 新增 `mx.hk 0/1`（注入钩子开关），用例期间隔离 |
| `mx.lf` 合成帧偶发丢失 | 自环字节与 1 kHz 真实流量**共用一个解析器** | `mx.lf` 改走**私有解析器** `makcu_link_probe_frame()`，不再经线缆 |
