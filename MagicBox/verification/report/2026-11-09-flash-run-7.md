# 上机记录：2026-11-09 第七批（鼠标提交层起步）

## 1. 本轮做了什么

把 `makcu_mouse` 的**队列/请求层**接上，让 `move`/`wheel`/`silent` 真的产生 HID 报告
（此前只有协议回显）。

| 原地址 | 实现 | 说明 |
|---|---|---|
| `0x42010BC4` `mouse_move` | `makcu_mouse_move_hook` | `mode<2` 走 default 提交，否则走 mode 提交 |
| `0x4200F8E4` `mouse_submit_default` | `submit_default()` | 写 pending dx/dy、置 move 标志、置提交请求并唤醒任务（对应 `DAT_42000E44/E48/E4C/E04`） |
| `0x4200F744` `mouse_submit_ext` | `makcu_mouse_move_ext_hook` | 5 参扩展形式（mode 1..0x3FF 的检查在协议层做） |
| `0x4200F96C` `wheel_submit` | `submit_wheel()` | 写 `DAT_42000E88` 的等价物 + 提交请求 |
| `0x42010D3C` `pulse_move` | `submit_pulse()` | 去程 → `vTaskDelay(1)` → 回程 |
| `0x4200F848` `mouse_commit_task` | `makcu_mouse_task()` | 等任务通知 → 取 pending → 发一份报告 |
| `0x4200EFEC` `mouse_submit`（Bezier 引擎） | **分阶段**：整段位移压成一份报告 | 32 KB 反编译、用到 `cos/sin/__fixdfsi`；接口与报告字段已就位，替换函数体即可接入 |

新增可观测点：`makcu_mouse_last_report()` + 台架命令 `mx.rp`（回 `dx dy wheel` 的十六进制），
这样在没有 USB HID 主机的情况下也能断言“报告里到底是什么”。

## 4. 当前边界

- 报告内容已可验证，但**轨迹形状**还不是原厂行为：Bezier 引擎（`0x4200EFEC`）未移植，
  现在是一步到位；原厂是分步插值 + 平滑；
- HID 报告还没真正发出去（`makcu_hiddev` 未移植），`makcu_hid_report_hook` 目前是台架桩；
- 下一步二选一：先把 Bezier 引擎啃下来（保真度提升大、工作量也大），或先接
  `makcu_hiddev` 让报告真的走 USB（能直接看鼠标动）。
