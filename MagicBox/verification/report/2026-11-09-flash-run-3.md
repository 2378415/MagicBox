# 上机记录：2026-11-09 第三批（cmd_silent / cmd_serial）

## 1. 本轮移植

| handler | opcode | 原地址 | 语义 |
|---|---|---|---|
| `cmd_silent` | 0x19 | `0x4200E1B0` | 与 `cmd_move` 同一套解析器；**只有 2 个参数**时动作（`pulse_move`，`0x42010D3C`）并回显，其它个数一律静默（`bnei a9, 2 → retw`） |
| `cmd_serial` | 0x1A | `0x4200DC84` | 查询（无参或 `)`）→ `"<Original/Spoofed> Serial : <sn>"` 或失败文案；`serial(0)` 恢复原厂；`serial("<串>")` 写伪装值（≤0x14）；成功回显、失败发失败文案 |

关键常量（从镜像直读，`0x3C036520` 起 0x24 字节）：

```
"Mouse does not have a serial number\n"   ← 36 字节，含尾部 NUL，原实现按 0x24 发送
"Original" / "Spoofed" / "%s Serial : %s"
```

新增挂接点（都留成函数指针，等 HID 层移植后再装）：

- `makcu_mouse_pulse_hook`（`0x42010D3C`：去程 → 等信号量 → 回程）
- `makcu_serial_read_hook`（`0x42010C84`：读 / 恢复 / 写三模式），当前返回“无序列号”，
  走的正是原厂未烧序列号时的那条分支

`handlers.def` 现标 8 支 `implemented`（0x05/0x06/0x08/0x09/0x0A/0x0C/0x19/0x1A）。

## 2. 烧录与回归

```
idf.py -p COM11 -b 921600 flash   ->  Hash of data verified / Done
```

回归（19 例）在**两条控制通路上各跑一遍**：

| 端口 | 结果 |
|---|---|
| `COM11`（原生 USB-Serial-JTAG） | **18 passed, 1 xpassed, 0 failed** |
| `COM8` （CH343 / UART0） | **18 passed, 1 xpassed, 0 failed** |

即：43 条命令表里 8 个 opcode 的协议面全部与原厂一致，`serial()` 的失败文案
（含尾部换行）与实测逐字节相同。

## 3. 与原厂的一个已知差异（记录，不修）

在“被克隆设备端口没有接主机”的台架上，原厂 `silent(x,y)` 会阻塞在
`pulse_move` 的信号量上（实测：`silent(0,0)` 无回包）；重建版因为运动层还没移植，
会立即回显。等 `makcu_mouse` 移植后自然对齐。

## 4. 回滚

```
esptool --port COM11 write_flash 0x0 work/hw_left_before_rebuild.bin
回读核对: 4194304/4194304 = 100.0000%   identical: True   app ver: 1
```

## 5. 结论

- 8 支 handler、19 条用例全绿，T2 在一个子集上“协议等价”成立；
- 剩余 19 个 opcode 全是未移植 handler（锁、按键按下/释放、点按、字符串输入、
  映射表、通道表、通道开关），其中 `cmd_lock_*` 四兄弟与 `cmd_key_*` 已有现成样板；
- 运动/键盘/HID 的实际副作用仍然待移植，目前只验证协议面。
