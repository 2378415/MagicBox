# 上机记录：2026-11-09 第十六批（13 个隐藏 opcode 的实测闭环）

> 目标：D9 写着“13 个隐藏 opcode 只实现已实证的部分，其余行为属推断”。本轮把它们从
> **“回包对得上”** 推到 **“回包 + 副作用都实测”**，并把两条“线上看不见”的写入路径
> （map 表、channel toggle 的 enable 位与 resend 标志）变成可复现的串口断言。

## 1. 为什么需要新探针

这 13 个 opcode（`0x08`、`0x0D`–`0x18`）在 43 条命令表里没有对应文本命令，只能靠
`MB_DEBUG_OPCODE` 的 `mx.<hex> <args>` 夹具调用。其中：

- `0x11 / 0x0F / 0x14` 的回包能证明参数解析；
- `0x15 / 0x16 / 0x18` 的回包只是**回显**，写到哪张表、写没写、resend 标志翻没翻，线上完全看不见。

于是加了两个**只用于台架构建**的探针（`app_left/main/app_main.c`，`MB_DEBUG_OPCODE` 下才编译）：

| 探针 | 作用 |
|---|---|
| `mx.dd` | 打印四张表 + resend 标志：`w=desc[+0x63+i]`、`w16=desc[+0x163+i]`、`en=desc[+0x269+i]`、`pr=desc[+0x369+i]`、`th=desc[+0x636+i]`（各 8/16 字节 hex）、`rs=`（`0x3FC99FA3`） |
| `mx.dp <idx>` | 只置 `pr[idx]`（present 位），用于在“从未见过真实通道表”的设备上触发 `0x18` 的写入分支 |

## 2. 13 个 opcode 的实测矩阵

| opcode | handler | 夹具命令 | 实测回包 | 副作用证据 |
|---|---|---|---|---|
| `0x08` | `cmd_nop` | `mx.08 hello` | `km.hello` | 无（纯回显；`mx.08` 不带参数时**无回包**，因为夹具把参数当命令行，空行长度为 0） |
| `0x0D` | `cmd_key_down` | `mx.0d 'a'` / `mx.0d 4` | `km.'a'` / `km.4` | `mx.rk` 出现含 usage 0x04 的报告 |
| `0x0E` | `cmd_key_up` | `mx.0e 'a'` | `km.'a'` | 报告清零 |
| `0x0F` | `cmd_key_tap` | `mx.0f 4,1,5` | `km.4,1,5` | 按下→延时→抬起两份报告 |
| `0x10` | `cmd_set_string` | `mx.10 'hi'` | `km.'hi'` | `mx.rk` 依次出现 h(0x0b)/i(0x0c) |
| `0x11` | `cmd_key_state` | `mx.11 'a'` | `km.mx\n0`（`<name>\n<digit>`；夹具的 name 是 `mx`） | 状态位随 `0x0D`/`0x0E` 变化 |
| `0x12` | `cmd_keys_down` | `mx.12 'a','b'` | `km.'a','b'` | `mx.rk` 出现 `04 05` 同时按下的报告 |
| `0x13` | `cmd_keys_up` | `mx.13 'a','b'` | `km.'a','b'` | 报告清空 |
| `0x14` | `cmd_keys_combo` | `mx.14 'a',1,2` | `km.'a',1,2` | 组合按下→延时→释放 |
| `0x15` | `cmd_map_16` | `mx.15 3,1` | `km.3,1` | **`w16[3]` 0→1**（`mx.dd`），`w` 不动 |
| `0x16` | `cmd_map_entry` | `mx.16 3,1` | `km.3,1` | **`w[3]` 0→1**（`mx.dd`），`w16` 不动 |
| `0x17` | `cmd_dump_channels` | `mx.17` | `km.0` | 三标志（en/pr/th）无一满足时回 `"0"` |
| `0x18` | `cmd_channel_toggle` | `mx.18 5,1` / `5,0` | `km.5,1` / `km.5,0` | **`en[5]` 1→0、`rs` 0→1**（`mx.dd`） |

## 3. 三个关键判据（都有正反例）

### 3.1 两张 map 表是分开的

```
mx.dd  -> w=0000000000000000 w16=0000000000000000 ...      （基线）
mx.15 3,1 -> km.3,1
mx.16 3,1 -> km.3,1
mx.dd  -> w=0000000100000000 w16=0000000100000000 ...      （各写各的第 3 字节）
```

### 3.2 `0x18` 被 present 位挡住（回显但**不写**）

```
mx.18 6,1 -> km.6,1                                        （present[6]=0）
mx.dd     -> en[6]=00, rs=0                                （回包有，状态没变）
```

### 3.3 放行后，enable 位与 resend 标志反向联动

```
mx.dp 5   -> km.1                                          （置 present[5]）
mx.18 5,1 -> km.5,1     mx.dd -> en[5]=01, rs=0
mx.18 5,0 -> km.5,0     mx.dd -> en[5]=00, rs=1            （清使能 → 置“需重发”）
```

这三条把 `cmd_channel_toggle` 的骨架（`gate → 写 +0x269 → 写 0x3FC99FA3`）从“按反编译写的”
变成“板上实测的”，也是 D9 的推翻条件之一。

## 4. 顺手修的回归问题

- `test_protocol.py::test_hidden_opcode_not_reachable` 一直是 `xfail(strict=False)`，实际上每次都
  通过（xpass）→ 改成普通断言 `test_single_byte_frame_is_dropped`，不再有“假失败/假通过”；
- 新增 4 条副作用断言（`test_hidden_opcodes.py`）：`0x08` 回显、两张 map 表各写各的、
  `0x18` 的 present 门、`0x18` 的 enable/resend 联动。

回归结果：**79 passed + 1 xpassed**（清洁控制台构建，COM3）；`mx.dd`/`mx.dp` 只能出现在
`MB_DEBUG_OPCODE` 构建里（与 D17 一致）。

## 5. JTAG 顺带结论（本轮试过，记录在此）

- openocd 能连、能读活体变量（见 run-15）；
- 但 **`monitor halt` 在这个 target 上会做一次核复位**，于是“改内存 → 跑命令 → 再读”的观测
  序列不可靠（RAM 会被 `s_dev` 的静态初始化覆盖）。所以本轮改用串口探针，可复现、可回归；
- JTAG 更适合的场合仍是**断点/单步**（下轮做 `0xA0` EP0 隧道时用它看右片帧）。
