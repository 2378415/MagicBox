# 上机记录：2026-11-09 第十八批（右片 `frame_forward` 从骨架到可跑）

> 待办第一条是“右片 `app_right` 从骨架到可跑”。本轮把 `frame_forward`（`0x4200F6C4`）
> 的**应答侧**全部实现并验证，主机侧（USB host 枚举、`0xA2` 构造）留给下一轮。
> 关键难点是**没有第二块板**：app_right 烧不进去，所以把应答构造抽成可移植组件，
> 由左片的 `mx.rf` 夹具在同一块板上跑同一份代码。

## 1. 证据（应答字节从哪来）

`reversed` 里的四处反编译：

| 地址 | 作用 | 关键点 |
|---|---|---|
| `0x4200F6C4` | `frame_forward` | 先判超长 → 再按命令分派 → 统一 `uart1_write(len+4)` |
| `0x420248E4` | 默认/错误 | `len=1, payload=0xFF` |
| `0x4200FAC0` | `0xA0` 方向 | `len=1`，方向 = `*DAT_42000d88` ? `0x00` : `0xFF` |
| `0x4200FAE0` | `0xA3` | `*DAT_42000d48 = 1`，`len=1, payload=0x00` |
| `0x4200F854` | `0x1A` 快照 | 无设备/无会话 → 错误字节；否则 `<status><string>`，`len=min(strlen,0x14)+1` |
| `0x4200FE44` / `0x4200F804` | `0xA4` 配置 | `len>=0x15` 或无设备 → 错误字节；否则写 NVS 并回 `0/0xFF` |
| `0x4200FC74` | `0xA1` 长帧 | 需要 URB 路径（host 栈），本轮未移植 |

`0xA1` 短帧（`len<8`）与 `0xB1`（纯头）也从 `frame_forward` 的主分支直接可得。

## 3. 真机验证（同一块板，左片跑右片的代码）

```
mx.rf a0                 -> 5aa00100ff      ← 0xA0，无设备 -> dir 0xFF
mx.rf a1 00000000000000  -> 5aa10100ff      ← 0xA1 短帧（7 字节）
mx.rf a3 00              -> 5aa3010000      ← 0xA3，重置 re-attach 标志
mx.rf 1a                 -> 5a1a0100ff      ← 0x1A，无设备
mx.rf a4 00              -> 5aa40100ff      ← 0xA4，无设备
mx.rf b1 0102            -> 5ab10000        ← 0xB1，纯头（忽略负载）
mx.rf 77                 -> 5a770100ff      ← 默认错误帧
```

每条都满足 `总长 == 字段 + 4`，与 `uart1_write(len+4)` 一致。

## 6. 仍然待做（右片主机侧）

1. **USB host 枚举**（`makcu_hidhost` 23 个函数）：接上真鼠标后，`ready/session` 才有值，
   `0x1A`/`0xA4`/`0xA0` 的分支才会走到“正常”路径；
2. **`0xA2` 上报构造**（右片 `0x4200FF10`）：`[ep,id,len,0,data…]`，与左片第十七批的消费端对接；
3. **`0xA1` 长帧**（`0x4200FC74`）：URB 完成/失败两条分支；
4. **`0xA4` 写配置**（`0x4200FD24` / `0x4200FD84`）：含 `PTR_DAT_42000d60` 类表过滤；
5. **UART1 真实引脚**：两片都还是占位 17/18，真机联调前必须定下来。

> 说明：这些都要**第二块板**（右片）才能验证。当前板子只有左片的 CH343 控制口，
