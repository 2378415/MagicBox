# sumv：拟人化相对移动（1000 Hz）落地记录

> 2026-11-10 18:15–18:40 实施。用户决策：**盒子算轨迹 / 1000 Hz 采样 / speed 用 counts/s / 滚轮透传 / REPLACE 不补**。

## 1. 最终语义

```
sumv(dx, dy [, speed [, mode [, dur_ms]]])
  · 采样 1000 Hz（esp_timer 1000 µs），一条命令 = 一条完整轨迹
  · speed（counts/s，默认 400，范围 50–8000）：T_ms = clamp(1000·D/speed, 40, 5000)
  · 执行期间真实鼠标的 X/Y 被丢弃，按键与滚轮透传
  · Σ 发出的 counts 精确等于请求（亚计数 DDA）
  · 再次调用 = REPLACE（剩余丢弃，aborted++）
```

`mode`：bit0 固定时长 · bit1 手颤(8–12 Hz) · bit2 子运动(1–3 峰) · bit3 过冲回拉。
**bit4 微停顿已于 2026-11-10 移除**（观感像卡顿），默认 mode 从 0x1E 改为 0x0E；实测连跑 5 次 `total_samples` 恒等于 `T_ms`、`mx.rt` 每次精确 +600。

## 2. 引擎

```
esp_timer 1000µs → km_sumv 任务(prio 13)
  u   = minjerk_q16(i, n)                 // 16.16 定点
  u  += 子运动峰（抛物线，1–3 个）
  p   = 折线查表(三次贝塞尔, 64 段, 按弧长) + 过冲回拉 + 手颤(三角波垂直偏移)
  Δ   = (p >> 16) − 已发位置              // 亚计数 DDA → 每样本 0–2 counts
  → makcu_mouse_emit_now(Δ)
```

控制点：`P1 = D/3 + 垂直·o1 + 沿路·j1`、`P2 = 2D/3 + 垂直·o2 + 沿路·j2`，
`o ∈ ±span/12`、`j ∈ ±10% span` —— 每次调用随机，`seed≠0` 时可复现。

## 3. 屏蔽（`link_report_to_mouse()` 的一跳）

| 输入 | 行为 |
|---|---|
| 真实鼠标 X/Y | 丢弃（`muted++`） |
| 真实鼠标按键/滚轮 | 透传；只在 `(buttons,wheel,pan)` 变化时发（否则零位移报告会吃光端点时隙） |
| `.km.move` / `MOTION_PLAN` | 拒绝（`move_hook_guarded`） |
| `.km.wheel` / `WHEEL` | 照常 |
| 键盘/厂商通道 | 不受影响 |

## 4. 接口

**km（opcode 0x1B / 0x1C，重建扩展）**

```
.km.sumv(400,0)                 .km.sumv(400,0,800)          .km.sumv(400,0,400,30)
.km.sumv()      -> sumv()\n0|1|2      .km.sumv_stop()
```

**二进制（控制口 921600 fast path）**

| cmd | payload | 回包 |
|---|---|---|
| `0x36 SUMV` | dx i16, dy i16, speed u16, mode u8, seed u8 [, dur u16] | 无 |
| `0x37 SUMV_STOP` | — | 无 |
| `0x38 SUMV_STATE` | — | active, samples, aborted, rounds, muted, btn_fwd, speed_eff, remain_ms |

台架探针 `mx.sv` 同内容；`tools/link_probe.py --sumv dx dy --speed N`。

## 5. 实测（18:35，speed=400）

```
speed=400, dx=800   ->  mx.sv: 0,2000,0,1,0,0,400,0     （2000 样本 = 2000 ms）
                        mx.rt: +800 精确守恒

速度对照             ->  speed 200 → 2000 ms；speed 800 → 500 ms（各 ±10% 内）
二进制 SUMV          ->  remain_ms 1250→650 递减，samples 以 1000/s 增长
回归                 ->  100 passed
```

## 6. 这轮踩的两个 bug

1. **min-jerk 定点量纲错**：`t³·(10 − 15t + 6t²)` 里把 `6t²` 写成了 `6`，t→1 时内层变负，
   曲线尾部来回甩 → 注入输出成 ±127 震荡（trace 里每 1 ms 一块 127）。修正后
   `u(0.5)=0.5`、`u(1)=1` 自检通过。
2. **`makcu_mouse_pump()` 抢 pending**：pump 在每次 HID 完成回调都会取走 pending 并发
   一条 ±127，把 `run_move()` 的 3 步移动拆散（回归 `test_two_axis_split_sums` 偶发失败）。
   现在 `run_move` 期间置 `s_moving`，pump 直接返回。

## 9. 2026-11-11 追加：移除过冲回拉 + 新增粘滞收尾

**改动**

| # | 内容 |
|---|---|
| 1 | 删除过冲回拉整层：`sumv_t` 去掉 `over_k / ext_dx / ext_dy`，折线终点直接用 `(dx,dy)`，删掉 `emit_sample()` 里的"最后 20% 拉回"块；bit3 退役（传了无效） |
| 2 | 新增粘滞收尾：`u > 0.95` 时减去 `bump(x)·SUMV_TAIL_A`（`bump = 4x(1−x)`，u=1 处归零 → 终点精确），尾段速度约 −18%；bit5 可关 |
| 3 | 默认 mode `0x0E → 0x06`（手颤 + 子运动 + 粘滞收尾），三处同步（`makcu_sumv.h` / `cmd_sumv.c` / `link_probe.py`） |

**实测（speed=400）**

```
dx=600 :  mx.sv samples=1500(=T_ms)  Σdx=600  过程最大 cumX=600   ← 无过冲
dx=2000:  T=5000 ms  到达占比的时刻（ms）:
            50% 2502 | 90% 3768 | 95% 4053 | 97.5% 4358 | 100% 5000
          同条件关掉粘滞（mode=0x26）:  97.5% → 4265   ⇒ 尾段晚 +93 ms
          Σdx=2000、过程最大=2000（无过冲）
回归    : 100 passed
```

**为什么"过冲"当初看起来像 bug**：它把终点延长 2–3%，于是**过程**累计会超过请求值，
`mx.rt` 只在最后才回到精确值——观感上是"冲过去再缩回来"，对点到点操作反而不像人。
现在的形态是"一路走到底 + 尾段略微粘滞"，过程量全程单调不越界。

**顺带**：这轮还发现"克隆偶尔退回 4 字节夹具"会让真实鼠标的 7 字节报告被当 12-bit 解、
`mx.rq` 里全是垃圾位移，从而打翻一批 trace 断言。试过"长度不符就请求重克隆"，但它会
在测试中途触发重新枚举、日志插进协议流，又把逐字节用例打翻——已回退，维持"开机护栏 +
`mx.rs`"的既有兜底（HANDOVER §14.7 第 7 条）。

## 10. 2026-11-11 追加：瞄准模式（FPS 拉枪线）

**动机**：手颤 + 子运动 + min-jerk 的"人味"在瞄准场景反而碍事——起步 20% / 收尾 20% 的缓动
让每一枪都"先顿一下再爬"，路径 8% 的随机弧让光标轨迹不是一条线。

**改动**

| # | 内容 |
|---|---|
| 1 | 速度剖面新增 `profile_linear` / `profile_trapezoid`（raised-cosine 斜坡 + 恒速段），65 点累计进度 LUT，热路径只查表 |
| 2 | 按距离分档：`D≤10` 单发（n=1）；`D≤60` 恒速 + 纯直线（控制点落在连线上）；`61–300` 进6%/出10%；`301–800` 8%/12%；`>800` 10%/15% |
| 3 | 路径弧度：瞄准模式 `span/60`（弧高 ≈1.25%），并删掉沿路径 ±10% 抖动；拟人模式仍 `span/12` + 抖动 |
| 4 | 手颤/子运动改为**仅拟人模式**；粘滞收尾改为 `D ≥ 600` 才生效、瞄准模式强度减半（280 vs 560） |
| 5 | 新增 `bit6 = 拟人模式`；默认 mode `0x06 → 0x00`（瞄准模式），三处同步（`makcu_sumv.h` / `cmd_sumv.c` / `link_probe.py`） |
| 6 | 老客户端传 `0x06/0x0E/0x1E`：bit6=0 → 抖动位被忽略，自动落到"不抖"的瞄准手感 |

**实测（speed=2000，瞄准模式）**

| 距离 | 总时长 | 起步 0–5% | 尾段 95–100% | Σ / 过程最大 | 说明 |
|---|---|---|---|---|---|
| 30 | 38 ms | 1 ms（2.6%） | 1 ms（2.6%） | 30 / 30 | 贴脸微调，没有缓起缓收 |
| 300 | 149 ms | 11 ms（7.4%） | 14 ms（9.4%） | 300 / 300 | 常规甩枪 |
| 2000 | 999 ms | 93 ms（9.3%） | 117 ms（11.7%） | 2000 / 2000 | 大幅拉枪，尾段仍短促 |
| 300（`0x40`） | 147 ms | 26 ms（17.7%） | 28 ms（19.0%） | 300 / 300 | 拟人模式对照 |

路径平整度（纯 X 移动里出现 `dy≠0` 的样本数）：短 30 → **0/30**（纯直线）；中 300 → 4/144；长 2000 → 26/935。

**回归**：100 passed。

## 11. 2026-11-11 追加：速度上限放开（8000 → 65535 + 极速位）

**动机**：`speed` 钳在 8000、时长下限 40 ms，导致"短距离根本到不了标称速度"
（D=100 想要 8000 时被 40 ms 压到 2500）。

**改动**

| # | 内容 |
|---|---|
| 1 | `SUMV_SPEED_MAX 8000 → 65535`（speed 是 u16，协议同宽） |
| 2 | 时长下限从常数 40 ms 改成 **`ceil(D / max_report)`，最低 4 ms** —— 这就是"每报告不超过 max_report counts"，也定义了真上限 `1000 × max_report` |
| 3 | 新增 `max_report`（8–120，出厂 60）+ 台架命令 `mx.mv [speed [max_report]]`（读/写默认值，打印 `cap=`） |
| 4 | 新增 `mode.bit7` **极速**：`T = T_floor`，直接摸到上限 |
| 5 | 收尾补齐改**循环**（最多 8 发）：极速档缺口可 >127，单发补不完 |

**实测（Σ 全部精确）**

| 请求 | max_report | 时长 | speed_eff | 样本 | Σ |
|---|---|---|---|---|---|
| 2000 极速 | 60 | 33 ms | 58,823 | 34 | 2000 |
| 2000 极速 | 120 | 16 ms | 117,647 | 51 | 2000 |
| 8000 极速 | 120 | 66 ms | 119,402 | 118 | 8000 |
| 300 极速 | 120 | 3 ms | 75,000 | 4 | 300 |
| 2000 普通 400 | 60 | 4997 ms | 400 | 2002 | 2000 |

**踩到的坑**

1. **text 命令解析是 int16**：`.km.sumv(2000,0,127000)` 会被夹到 32767（实测 `eff=32786` 就是
   32000/61ms 的结果），所以"127000"这种值必须走二进制帧或干脆用 `bit7`；
2. **单发补齐不够**：mr=127 时每样本顶到 127，缺口 57/358 counts 补不回来 → 改循环；
3. `max_report` 实用上限定 **120**：留余量，避免每样本都撞 int8 钳位 127。

**回归**：100 passed（含新增的克隆护栏，见下）。

## 12. 2026-11-11 追加：回归噪声的根因（克隆夹具未恢复）

跑回归反复出现"某个 trace 断言成片失败"，一度以为是偶发。真实原因：
`test_clone_descriptors.py` 用 `mx.cl <n>` 装 4 字节出厂夹具，**文件末尾只发了 `mx.cl 1`
（还是夹具），从没恢复"克隆真实鼠标"**。按字母序后面的 `test_mouse_reports.py` 拿到的是
`mx.if=0 / bytes=4 desc=52`，真实鼠标的 7 字节报告被当 12-bit 解，`mx.rq`/`mx.rt` 全是垃圾。

修法：`conftest.py` 加 autouse 模块级 fixture `restore_real_clone` —— 每个模块结束检查
`mx.if`，不是 `2 …` 就 `mx.rs` 重启重克隆、等枚举回来再稳 2 s。

顺带发现"手工 `mx.rs` 之后立刻跑测试"也会踩到同一坑（重克隆还没枚举完），所以护栏里加了
2 s 稳定等待；这两条一起修完，回归才稳定 **100 passed**。

## 13. 2026-11-11 追加：每报告上限自动跟随速度

**问题**：固定 `max_report=12` 等于给速度钉了 12,000 counts/s 的顶——`t_floor = ceil(D/12)`
把更大的 speed 夹回去。实测 `speed=60000, D=600` 仍是 **49 ms**（`speed_eff=12,000`）。

**改动**：`mr_eff = 12 + (speed − 11000)/1000`，夹到 `[12,120]`；`bit7` 极速直接取 120；
`mx.mv <speed> 0` = 自动（出厂默认），非 0 仍是固定。

**实测（D=600，Σ 全精确）**

| speed | 实测时长 | 报告数 | 每报告 max | speed_eff |
|---|---|---|---|---|
| 11,000 | 52 ms | 53 | 13 | 11,111 |
| 12,000 | 49 ms | 50 | 14 | 12,000 |
| 20,000 | 29 ms | 30 | 23 | 20,000 |
| 40,000 | 14 ms | 15 | 45 | 40,000 |
| 60,000 | **9 ms** | 10 | 67 | 60,000 |
| 60,000 固定 mr=12（对照） | 49 ms | 50 | 14 | 12,000 |

`mx.mv` 读回：`400,auto,mr=12,cap=12000` · `60000,auto,mr=61,cap=61000` · `400,fixed,mr=12,cap=12000`。

**回归**：100 passed。

**精度**：增益已标定为常数 1.25 px/count、与每报告大小无关，所以 mr 变大只影响"每跳多少像素"
（mr=61 → 约 76 px/跳），不影响落点精度（Σ 守恒）。

## 14. 2026-11-11 追加：瞄准专用优化（AIM）

**动机**：闭环瞄准每帧一条指令，客户端不该关心 `speed`/`mr`/counts；同时补掉三处
"作为执行器不合格"的地方（竞态、时长不可控、收尾爆发）。

| # | 改动 | 实测 |
|---|---|---|
| 1 | 新增 `0x3C AIM`（`dx,dy,max_ms,flags[,dead_min]`）与 `0x3D AIM_STATE`（12 B） | `AIM(300, ms=8)` → 7 ms / 8 报告 / Σ=300 |
| 2 | 死区：残差 ≤ `dead_min`（默认 2 counts）直接回"已到位" | `AIM(2)` → 0 报告，`last_result=4` |
| 3 | `dur_ms` 不再被 `mr` 地板抬高 | `sumv(600,dur=8)` → **7 ms**（以前被抬到 50 ms） |
| 4 | 首样本立即发（`xTaskNotifyGive`）+ 进度取 `prof_at(i+1)` | 首样本延迟 ≤1 ms → ~0.2 ms |
| 5 | 收尾补齐改"每 ms 最多一发" | 极速 2000 counts：16 ms / 17 报告 / **最大间隔 1011 µs**（不再 1 ms 内连发 8 条） |
| 6 | 轨迹代数 `s_gen`：REPLACE 后旧样本直接丢弃 | 消掉"控制任务改 `s_v`、采样任务正在读"的竞态后果 |
| 7 | 建路径失败 → 回滚旧轨迹继续跑 | 不再"停在半路" |
| 8 | 看门狗：`total_samples + 500 ms` 仍在跑就强制停 | `last_result=5` |

**顺带修掉的长期问题**：开机 autoclone 单次探测失败就退夹具 → 真实 7 字节报告被按 12-bit 解，
回归"成片失败"。现在开机**重试 10 × 300 ms**；刷入后 **100 passed**。

**服务端视角的闭环用法**：`AIM(counts, max_ms)` 每帧一条；`AIM_STATE` 看 `last_result/active`
判断是否完成；要停用 `SUMV_STOP`（`AIM(0,0)` 只会回"已到位"）。
