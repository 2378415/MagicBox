# 上机记录：2026-11-09 第二批（按键类 handler）

## 1. 本轮移植

| handler | opcode | 原地址 | 语义（逐条对照反编译） |
|---|---|---|---|
| `cmd_button_click` | 0x05 | `0x4200DFAC` | `dev==0` 静默；否则回 `<name>\n<flags>`，`flags = button_flags_get(dev,target)`（bit0 catch 槽、bit1 轴槽） |
| `cmd_buttons` | 0x0C | `0x4200DDBC` | `buttons()` / `buttons( )` → 查询并回 `<name>\n<mode>`；`buttons(0|1)` → 写模式后**回显**；其它 → 回显 |
| `cmd_catch_set` | 0x0A | `0x4200DF58` | 参数为空静默；`+0x54` 通道槽为空或参数非 0/1 → 回显；否则 `catch_set`（写 `+0x168`）+ 置 dirty + 回显 |

配套新增：

- `components/makcu_dev`：最小设备上下文（`tbl` `+0x210`、`desc` `+0x214`、buttons 模式、dirty），零初始化即“刚上电的设备”；
- `makcu_reply_status()`：`cmd_reply_status`（`0x4200DC18`）的等价实现，`buttons(` 系列统一归一到 `buttons()`——这正是实测回包 `km.buttons()\n0\r\n>>> ` 的来源；
- `handlers.def` 中 0x05 / 0x0A / 0x0C 标为 `implemented`（共 6 支已实现）。

链接核对（`nm`）：`cmd_button_click@0x4200d5fc`、`cmd_buttons@0x4200d64c`、
`cmd_catch_set@0x4200d710`、`makcu_reply_status@0x4200d918`、`makcu_dev_instance@0x4200d98c`。

## 4. 协议回归（19 例）

```
2 failed, 16 passed, 1 xpassed
```

通过的 16 例里，本批新增的 6 条是**逐字节**断言：

| 发送 | 收到（与实现一致） |
|---|---|
| `.km.buttons()` | `km.buttons()\n0\r\n>>> ` |
| `.km.buttons(1)` | `km.buttons(1)\r\n>>> ` |
| `.km.buttons(0)` | `km.buttons(0)\r\n>>> ` |
| `.km.left()` | `km.left()\n0\r\n>>> ` |
| `.km.right()` | `km.right()\n0\r\n>>> ` |
| `.km.catch_ml(1)` | `km.catch_ml(1)\r\n>>> ` |

失败的 2 例仍是未移植 handler，属预期：

- `.km.silent(0,0)` → `cmd_silent`（0x19）未移植（槽位 NULL）
- `.km.serial()` → `cmd_serial`（0x1A）未移植

## 6. 结论

- 按键类三支 handler 的**协议面与原厂一致**（回包字符串逐字节相同，含状态字节）；
- 设备上下文用零初始化即可复现“刚上电”的分支（通道未启用、buttons 模式 0），
  这也说明这三支 handler 的前置条件判断是对的；
- 运动/抓取的实际副作用仍待 HID 层移植（`catch_set` 只写表，不产生 HID 行为）。
