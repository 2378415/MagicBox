# 上机记录：2026-11-09 第八批（USB HID 设备打通）

## 1. 本轮做了什么

把 `makcu_hiddev` 从桩变成**真正的 USB HID 鼠标设备**，让报告真的走 USB。

| 项 | 内容 |
|---|---|
| 设备栈 | ESP-IDF 5.4 把 TinyUSB 移出核心组件，改用托管组件 `espressif/tinyusb`（`app_left/main/idf_component.yml` 添加依赖，已下载到 `managed_components/`） |
| PHY | 托管组件不带板级层，按它自带 BSP 的做法自己初始化：`usb_phy_config_t{USB_PHY_CTRL_OTG, USB_PHY_TARGET_INT, USB_OTG_MODE_DEVICE, USB_PHY_SPEED_FULL}` → `usb_new_phy()` |
| 描述符 | 设备 `VID 0x303A / PID 0x4004`、字符串 `MAKCU / MAKCU HID`、HID 报告 4 字节（buttons, dx, dy, wheel，无 Report ID） |
| 任务 | `tud_task()` 常驻任务；`tud_mount_cb/umount_cb` 维护挂载状态 |
| 上报 | `makcu_hid_report_hook = makcu_hiddev_report` → `tud_hid_report(0, report, 4)` |
| 链接 | HID 组件的回调被 TinyUSB 静态库引用，普通归档顺序会丢符号 → `idf_component_register(... WHOLE_ARCHIVE)` |
| 引脚冲突 | ESP32-S3 的 USB-Serial-JTAG 与 USB-OTG **共用 D+/D-**，所以启用 HID 时自动关闭 JTAG 控制台（`MB_HID_DEVICE=1` → `MB_CONTROL_USB_JTAG=0`），控制口只剩 UART0/CH343 |

## 2. 枚举证据

```
HID\VID_303A&PID_4004\...   HID-compliant mouse   OK
USB\VID_303A&PID_4004\...   USB 输入设备           OK
```

控制口同时仍有 `COM8`（CH343 / UART0）。

## 3. 端到端运动验证（`tools/cursor_test.ps1`）

读 Windows 光标位置 → 发命令 → 再读，差值如下：

| 发送 | 光标位移 | 说明 |
|---|---|---|
| `.km.move(60,40)` | **+54, +34** | 方向与量级一致（Windows 指针加速导致比例略小） |
| `.km.move(-60,-40)` | **-86, -57** | 反向（加速曲线不对称） |
| `.km.wheel(1)` | 0, 0 | 滚轮不移动光标（符合预期） |
| `.km.silent(25,15)` | **0, 0** | 去程+回程抵消 —— 正是 pulse 的语义 |

这是本项目第一次**端到端闭环**：文本命令 → 协议层 → 提交队列 → HID 报告 → 操作系统光标。

## 4. 新增：台架恢复通道

HID 构建在原生 USB 上没有 CDC 控制台，普通方式无法再烧录。因此在台架夹具里加了
`mx.dl`（`MB_DEBUG_OPCODE=ON` 时可用）：

```c
REG_WRITE(RTC_CNTL_OPTION1_REG, RTC_CNTL_FORCE_DOWNLOAD_BOOT);
esp_restart();
```

发一次即重启进 ROM 下载模式，原生 USB 重新枚举为 `COM9`，随后：

```
esptool --chip esp32s3 --port COM9 write_flash 0x0 work/hw_left_before_rebuild.bin
回读核对: 4194304/4194304 = 100.0000%   identical: True   app ver: 1
```

回滚完成，设备已复原原厂固件。
