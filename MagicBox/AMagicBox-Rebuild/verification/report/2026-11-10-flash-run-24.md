# 上机记录：2026-11-10 第二十五批（复合设备克隆：进展与卡点）

> 用户把自己的 **G3M PRO 无线鼠标**插到盒子上，出现同样的"y 轴偏快、x 轴偏慢"。
> 本轮把复合设备的读取打通了，但克隆出来的设备在 Windows 上**启动失败**，收尾时回退到
> 已验证的单接口配置。

## 1. 为什么换鼠标就"y 快 x 慢"

不是"每个鼠标要一套配置"，而是**这颗鼠标的报告格式与测试鼠标不同**：

| | 测试鼠标（30FA:0302） | G3M PRO（320F:706E） |
|---|---|---|
| 设备形态 | 单接口 | **复合设备：2 个 HID 接口** |
| 配置长度 | 34 B | **66 B**（bMaxPower 400 mA） |
| 鼠标接口报告描述符 | 64 B | **93 B** |
| 位移字段 | **12 位** | **16 位（±32767）** |
| 报告长度 | 5 B | **7 B**（5 键 + X16 + Y16 + 滚轮8 + AC pan8） |

按 12 位解 16 位数据 → 两轴都错，表现就是"一个快一个慢"。

## 2. 本轮打通的读取链路

1. **复合设备解析**：遍历配置描述符，找出 class=3 的接口，读它的报告描述符，用
   "是否含 `05 01 09 02`"判断是不是鼠标，然后**把配置裁剪成单接口**（配置 + 该接口 +
   HID + 其 IN 端点，接口号改 0，`wTotalLength`/`bNumInterfaces` 同步）。
2. **报告描述符必须用 `bmRequestType = 0x81`（标准 + 接口接收者）**：
   用 `0x80`（设备接收者）读测试鼠标可以，读这颗复合设备一律回错误帧。
   这是本轮的关键发现，`tunnel_get(0x22, ...)` 里已按类型切换。
3. 隧道单帧上限提到 **192 字节**（要装得下 93 字节描述符）。

实测：

```
mx.ac -> 1:320f:706e:93        克隆成功，取到鼠标接口的 93 字节报告描述符
dv    -> ...0f326e70...        VID 320F / PID 706E
PC 侧 -> USB\VID_320F&PID_706E\000000000003 出现
```

## 3. 卡点：克隆出的设备在 Windows 上启动失败

```
PC 侧 -> USB\VID_320F&PID_706E\000000000003   Error  CM_PROB_FAILED_START
固件  -> mnt=0（SET_CONFIGURATION 从未完成）、hr -> ready=0 suspended=1
```

试过但没有改善的两项：

- 把裁剪出的接口从 **boot 鼠标**（SubClass=1/Protocol=2）改成**通用 HID**（0/0）；
- 把 `bMaxPower` 从 400 mA 压到 100 mA。

对照：同一套固件用**测试鼠标**的单接口克隆一切正常（`mnt=1`、`ready=1`、PC 侧 OK），
所以不是 USB 栈本身的问题，而是**这份克隆配置/描述符链在枚举阶段被主机拒绝**。

## 4. 下一步（有明确优先级）

1. **抓总线**：装 USBPcap + Wireshark，抓一次失败枚举，直接看是哪条请求被打回
   （STALL / 长度不符 / 配置描述符校验失败）。这一步能把"猜"变成"看"。
2. 两个重点怀疑：
   - 这份 93 字节报告描述符里有 `95 40 75 08 B1 02`（**Feature 报告 512 位**），
     Windows 在 HID 启动阶段会查询 Feature 报告，而我们**没有实现
     `tud_hid_get_report_cb`**，可能因此中止；
   - 真正的多接口克隆（`CFG_TUD_HID=2` + 原封不动转发 66 字节配置 + 按 `0xA2` 的
     `ep` 字节把报告路由到对应接口）——`ep` 字段链路里本来就有，路由是现成的。
3. 若走多接口，`makcu_clone_t` 需要扩成"接口数组"（每项：接口号、报告描述符、端点）。

## 5. 现场状态（收尾时已恢复可用）

- 固件：`-DMB_CLONE_FIXTURE=3`（单接口、30FA 身份、12 位直送），`mnt=1`、`ready=1`、
  PC 侧 `USB\VID_30FA&PID_0302\000000000003` 为 OK；
- 复合设备自动克隆的代码**保留在仓库里**（`MB_CLONE_FIXTURE=99` 时启用），
  但默认构建不启用，避免把板子留在不可用状态；
- 已知限制：插 G3M PRO 时盒子会回退到 30FA 身份，位移按 12 位解 → 速度不对。
