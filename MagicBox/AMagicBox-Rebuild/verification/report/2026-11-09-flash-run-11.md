## 2. 复合 HID 描述符

一个 HID 接口、两个 Report ID：

- **ID 1 = 鼠标**：buttons, dx, dy, wheel（4 字节）
- **ID 2 = 键盘**：modifiers, reserved, usage0..usage5（8 字节，boot keyboard 布局）

Windows 枚举结果（同一台 `VID_303A&PID_4004`）：

```
HID\VID_303A&PID_4004&COL01  HID-compliant mouse
HID\VID_303A&PID_4004&COL02  HID Keyboard Device
USB\VID_303A&PID_4004        USB 输入设备
```

## 4. 一个"看起来像 bug"的现象，查清是测量被污染

光标测试第一轮出现离谱数字（`.km.move(60,40)` 量到 `+94,+232`，`wheel(1)` 量到 `+56,-93`）。
一度怀疑"键盘 8 字节报告插进鼠标 4 字节报告"的竞态，于是给 HID 发送加了互斥锁。

但用新写的 `tools/hid_isolation.ps1` 在**加锁前后都测**：

```
wheel-only            delta = 0,0
键盘流量后再来纯滚轮    delta = 0,0
键盘流量后小位移        dx = 34
PASS
```

结论：加锁前就已经通过——**那些离谱数字是因为测量时上一轮回归的 600 px 曲线位移还在队列里排空**，
不是固件竞态。互斥锁保留（同一端点从两个任务写本来就该串行化），但**竞态假设未被证实**，记录在此以免误传。

设备空闲后重测，数字干净且对称：

| 动作 | 光标位移 |
|---|---|
| `.km.move(60,40)` | **+88, +58** |
| `.km.move(-60,-40)` | **-87, -57** |
| `.km.wheel(1)` | 0, 0 |
| `.km.silent(25,15)` | 0, 0 |

比例 >1 来自 Windows 指针加速，"静默"与"滚轮"都不动光标，正是应有行为。
