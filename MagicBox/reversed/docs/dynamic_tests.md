# 动态测试记录（真机）

硬件：MAKCU 双 ESP32-S3 盒子，左片 V3.2（device 侧）、右片 V3.7（host 侧），均与官方镜像一致。
日期：2026-11-09。

---

## 1. 设备与端口

| 口 | 枚举 | 说明 |
|---|---|---|
| 中间 CH343 | `USB-Enhanced-SERIAL CH343 (COM8)`，`VID_1A86&PID_55D3` | 运行期控制口 |
| 左片原生 USB | `VID_303A&PID_0009`（下载模式） | 刷机口，也是运行期“被克隆设备” |
| 右片原生 USB | `VID_303A&PID_1001` | 右片下载/调试 |

**关键经验**：CH343 只要供电就会枚举，端口存在 ≠ 应用在跑。应用卡住时端口在、但完全无响应；**必须发一次 DTR/RTS 复位脉冲**（`DTR=false→true`、`RTS=true→false`）才会恢复正常。

## 4. 通信实测

### 4.1 成功用例

```
发送: .km.version()\r        （0x2E 6B 6D 2E 76 65 72 73 69 6F 6E 28 29 0D）
接收: km.MAKCU\r\n>>>        （6B 6D 2E 4D 41 4B 43 55 0D 0A 3E 3E 3E 20）
```

- 波特率 **115200**，8N1；
- 文本帧必须带 **`.` 前缀**（`0x2E`），与 `frame_router`（`0x4200DB04`）的静态分析一致；
- 回包格式与协议表里的 `km.MAKCU` + `>>> ` 完全吻合。

### 4.2 波特率扫描（复位前）

9600 / 19200 / 38400 / 57600 / 115200 / 230400 / 460800 / 921600 / 1M / 1.5M / 2M / 3M / 4M / 5M / 6M，全部 0 字节——当时的静默是“未复位”导致，与波特率无关。

### 4.3 保留 opcode 探测（复位后，单字节）

| 发送 | 回应 |
|---|---|
| `0x08`、`0x0D`–`0x18`（13 个） | **全部无回应** |
| `0xA1`、`0xA2`、`0xA4`（单字节） | 也全部无回应 |

结论：单字节帧被判为不完整帧丢弃，**不会**进入 opcode 跳表。13 个隐藏处理函数在 UART0 外部链路上不可达，由“静态推断”升级为**实测结论**。

## 6. 文本命令实测（复位后，115200）

| 发送 | 接收 | 解读 |
|---|---|---|
| `.km.buttons()` | `km.buttons()\n0\r\n>>> ` | 回显 + 状态字节 `0`（当前模式） |
| `.km.left()` | `km.left()\n0\r\n>>> ` | 回显 + 状态 `0` |
| `.km.move(10,5)` | `km.move(10,5)\r\n>>> ` | 回显，无状态字节 |
| `.km.catch_ml(1)` | `km.catch_ml(1)\r\n>>> ` | 回显，无状态字节 |

结论：响应格式 = `km.<原命令>` + 可选 `\n<状态>` + `\r\n>>> `，与 `uart0_reply` 的调用点一致。

## 7. 二进制成帧实测

| 发送 | 接收 |
|---|---|
| `5A A1 00 00` | none |
| `5A A4 00 00` | none |

说明 `5A <cmd> <len>` 帧**不是外部 UART0 的格式**，只用于片间 UART1——与静态分析一致：UART0 的 `frame_router` 按首字节认 `0x2E/0xA1/0xA2/0xA4/0xA5`，不认 `0x5A`。

## 8. `silent` 命令语义（实测）

| 发送 | 接收 |
|---|---|
| `.km.silent()` | 无 |
| `.km.silent(0)` | 无 |
| `.km.silent(1)` | 无 |
| `.km.version()`（对照） | `km.MAKCU\r\n>>> ` |

三种形式全部无回包，对照命令正常 → **`silent(`（opcode 0x19）成功时刻意不调用 `uart0_reply`**，用“无应答”表示成功。与静态分析中该 handler 没有明显回执分支一致。

另记：`km.version` 与 `km.version()` 都可，证明命令表为前缀匹配。

## 9. 黑盒测试：错误处理行为

| 发送 | 回应 | 解读 |
|---|---|---|
| `.km.foobar()` | **无任何回应**（连提示符都没有） | 一级查表失败直接返回，无兜底回复 |
| `.km.version(` | `km.MAKCU\r\n>>> ` | 前缀匹配即执行，不校验括号 |
| `.km.move(1)` | 回显 + 提示符，无动作 | `n<2` 只回执 |
| `.km.move(1,2,3)` | 回显 + 提示符 | 3/4 参数不匹配任何分支 |
| `.km.buttons(2)` | 回显 + 提示符 | 参数非 0/1，静默忽略 |
| `.km.catch_ml(9)` | 回显 + 提示符 | 越界，静默忽略 |
| `.km.lock_mx(5000)` | 回显 + 提示符 | 被接受（int16 内），锁值钳位 |

结论：未知命令零回应；命令按表项长度前缀匹配、不校验括号；参数越界一律“只回执不动作”。

## 10. `silent(` 的参数个数与回执（本轮新增，用于关闭问题 #2）

背景：补丁版反编译把 `cmd_silent`（`0x4200E1B0`）的函数体判成不可达，只剩
`return;`。这跟"该 handler 有没有实现"冲突，所以直接上机测参数个数。

| 发送 | 接收 | 解读 |
|---|---|---|
| `.km.version()` | `km.MAKCU\r\n>>> ` | 对照组正常 |
| `.km.silent()` | 无 | 0 个参数 → 静默返回 |
| `.km.silent(0)` | 无 | 1 个参数 → 静默返回 |
| `.km.silent(0,0)` | `km.silent(0,0)\r\n>>> ` | **2 个参数 → 走完主干并回执** |
| `.km.version()` | `km.MAKCU\r\n>>> ` | 复位后对照仍正常 |

结论：

1. `silent(` 的**回执是有条件的**：`<2` 个参数零回应，`>=2` 个参数才回显整行；
2. 因此函数体**可达**，补丁版反编译里那个"恒 return"是常量折叠假象 ——
   `excw` 在这类前置校验里不是 no-op（`known_gaps.md` 保留它的兜底汇编）；
3. 回包形状（回显整行 + `>>> `）与 `uart0_reply(buf, len, 0)` 一致，
   而 `buttons()` 的 `\n<状态>` 是 handler 自己拼在回显后面的。

脚本：`tools/flash/send_cmd.py`（自动 DTR/RTS 复位脉冲，然后逐条发送并打印
十六进制回包）。

## 11. `serial(` 查询（验证跳表专用 handler 的存在）

`serial(` 的 handler（opcode 0x1A，`0x4200DC84`）在反编译里没有函数体 —— 没有
`call8` 调用点，Ghidra 从未在那里建函数，所以本轮先按跳表地址手工重建，再用
文本命令验证它确实存在、确实走这条路径。

| 发送 | 接收（hex 见脚本输出） | 解读 |
|---|---|---|
| `.km.serial()` | `km.Mouse does not have a serial number\n\r\n>>> ` | handler 存在且可达；本机未烧序列号 → 走失败文案 |
| `.km.version()` | `km.MAKCU\r\n>>> ` | 对照 |

由此确认两件事：

1. **`uart0_reply(buf, len, 0)` 的封装格式**是 `"km." + 内容 + "\r\n>>> "`
   （`0x420143E8` 里 3 字节前缀 + 内容 + 6 字节尾巴），所以 `silent` 的
   “回显整行”与 `serial` 的固定文案都落在这个壳里；
2. 失败文案的实际字符串是 **`Mouse does not have a serial number`**，
   长度参数在伪代码里是 `0x24`（36），比可见字符多出的部分是尾随换行。
