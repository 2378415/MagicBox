# MAKCU V3.2 左片命令协议（静态逆向还原）

> 来源：`官方固件/V3.2_LEFT.bin`（sha256 `ca7a71b4…a3a580`）静态分析。
> 所有地址均为镜像内虚拟地址（IROM `0x4200xxxx`、DROM `0x3C0xxxxx`）。
> 标记说明：**[观察]** = 直接从数据/代码读出；**[推断]** = 由字段取值与处理函数行为推得，未实机验证。

## 1. 传输与分帧

| 项 | 值 | 依据 |
|---|---|---|
| 物理链路 | CH343 USB-串口（VID `1A86` / PID `55D3`） | 官方文档 + 固件内 `uart_set_pin`/`uart_param_config` 调用 |
| 默认波特率 | 115200，运行时可切 4 Mbps / 6 Mbps | NVS 键 `baud_rate`；日志串 `MAKCU baud rate successfully changed to %u` |
| 命令前缀 | `km.` | 字符串 `0x3C03E38C` |
| 应答提示符 | `>>> ` | 字符串 `0x3C03E386` |
| 帧结束 | `\r`（CR） | 与官方上位机示例 `km.version()\r` 一致 |

**解析链路** [观察]：

```
UART0 中断/驱动
  └─ uart0_in           0x420142A0   建队列、装驱动、起 4 个任务
       ├─ UART0_Send_Task      0x42014369
       ├─ UART0FrameConsumer   0x42014393   ← 取帧、去前缀、查表
       └─ Reset_Baud_Rate_Task

                 └─ FUN_4200EEC4 0x4200EEC4 ← 一级查表（前缀匹配）
```

`FUN_4200EEC4` 的匹配逻辑（伪代码，已反编译）：

```c
entry = table;                       // 0x3C03DF74
do {
    len = entry->len;
    if (len <= input_len && strncmp(input, entry->name, len) == 0)
        return entry;                // 命中，返回条目指针
    entry = (entry_t*)((char*)entry + 0x14);   // 步长 20 字节
} while (entry->name != NULL);
return NULL;
```

## 2. 表结构 [观察 + 推断]

每条 20 字节，位于 `0x3C03DF74`，共 **43 条**：

```c
typedef struct {
    const char *name;   // +0x00  命令字面量（含 "()" 或 "(" 后缀）
    uint32_t    len;    // +0x04  参与 strncmp 的字节数
    uint32_t    argc;   // +0x08  期望参数个数（0/1/2/3）

} cmd_entry_t;
```

`argc`/`target`/`opcode` 的语义由处理函数用法反推（见 §4），字段位置与步长是硬观察。

## 5. 处理函数语义（反编译片段）

### 5.1 `buttons`（opcode 0x0C，`0x4200DDBC`）

```c
if (strncmp(cmd, "buttons()", 9) == 0) { /* 查询/默认路径 */ ... }
else if (argc == 2 && arg[0] in {'0','1'} && arg[1] == ')') {
    FUN_42010c44(dev, arg[0] == '1');   // 设置开关
    reply(...);
}
```

`argc == 1` 时要求 `*arg == ')'`，与 `buttons(` 的 8 字节前缀互补 —— 即 `buttons()` 与 `buttons(0)` / `buttons(1)` 都合法。

### 5.2 `version`（opcode 0x09，`0x4200DC6C`）

```c
FUN_42010c30(buf, &len);          // 取版本串
FUN_420143e8(buf, len, 0);        // 回写控制口
```

### 5.3 `catch_m*(`（opcode 0x0A，`0x4200DF58`）

```c
if (argc != 0) {
    if (dev->catch[target] == NULL || (arg[0]-'0') > 1)
        reply(...);               // 未启用或参数越界 → 仅回执
    else {
        FUN_4202D1AC(dev, target, arg[0] == '1');   // 开/关抓取
        *flag = 1;
        reply(...);
    }
}
```

即 `catch_ml(1)` 打开左键抓取、`catch_ml(0)` 关闭；对未开启抓取的通道发命令只回执不生效。

### 5.4 `left(` 系列（opcode 0x04/0x05）

同一 `target` 上：`()` 形式走 0x05（单击/脉冲），`(` 形式走 0x04（按下/释放，按参数 0/1）。`target` 1–5 对应 左/右/中/侧1/侧2。

### 5.5 `silent(`（opcode 0x19，`0x4200E1B0`）：静默移动

参数语义与 `move(` 完全同构（同一套解析循环），差别在**回执条件**与 `n==2`
的动作：

| 参数个数 | 行为 | 实测回包 |
|---:|---|---|
| 0 / 1 | 静默返回，不动作不回执 | 无 |
| 2 | `pulse_move(dev, x, y)`：移动 → 等提交信号量 → `vTaskDelay(1)` → 反向移动 | `km.silent(x,y)\r\n>>> ` |
| 3 / 4 | `mouse_move(dev, x, y, mode=v[2]（<2 时取 1）)` | 回显 + `>>> ` |
| 5 | `mouse_submit_ext(dev, v0..v4)`（与 `move(` 的 5 参分支相同） | 回显 + `>>> ` |

```c
if (dev == 0) return;                 /* 0x4200E1BF：a4 判空，静默 */
/* 0x4200E1C4 的三字节指令无译码（objdump 显示 excw） */
if (n < 2) return;                    /* 静默：无回显、无提示符 */
```

`pulse_move`（`0x42010D3C`）= 去程提交 + 回程提交，用于"位移但不改变最终位置"的
场景。完整 C 见 `reversed/docs/reconstruction_patterns.md` §3，硬件证据见
`reversed/docs/dynamic_tests.md` §10。

### 5.6 `serial(`（opcode 0x1A，`0x4200DC84`）：序列号伪装

| 形式 | 行为 | 回包 |
|---|---|---|
| `serial()` / `serial()` 形式的 `(` 后紧跟 `)` | 查询当前序列号 | `Original: <串>` / `Spoofed: <串>`，失败回 `Mouse does not have a serial number` |
| `serial(0)` | 恢复原厂序列号 | 回显整行 |
| `serial("<串>")` | 写入伪装序列号（截断到 20 字节） | 回显整行 |

底层是 `serial_read`（`0x42010C84`），模式 `0` 读、`1` 恢复、`2` 写。

### 5.7 `map_entry` 写表项（opcode 0x16，`0x4200E624`）

`"<index>,<value>"` 形式，两个值都必须非零才写入（`map_entry_write`，
`0x4202D4DC`），写后回显整行。与 opcode 0x15（`0x4200EA04`）的区别是第二个值
走完整 `parse_int_or_char`（支持 `'c'` 字符），0x15 只取一位十进制。

## 9. `move(` / `wheel(` 处理函数完整还原

Ghidra 的 Xtensa 模块在 `0x4200E162`、`0x4200E3A3` 处遇到 `excw`（Xtensa 异常等待占位指令，GCC 的 errata 补丁会发）后中止了反编译。改用 **ESP-IDF 官方工具链 objdump 2.43.1**（`xtensa-esp-elf-14.2.0`）对 IROM 段区间反汇编，两条处理函数已完整解出。

### 9.1 公共整数解析器（`move(` 前半段，`0x4200E04A`–`0x4200E15C`）

```c
// 逐字符解析，最多 5 个值，结果按 int16 顺序存到栈数组
while (idx < len) {
    if (c == ',' || c == ')') { idx++; tokens++; continue; }   // 分隔符
    while (c == ' ' || c == '\t') idx++;                        // 跳过空白
    sign = (c == '-') ? -1 : +1;                                // '+' 也接受
    if (c == '-' || c == '+') idx++;
    v = 0; seen = 0;
    while (digit(c)) { v = v*10 + (c-'0'); seen = 1; idx++; }   // addx4+addx2 展开
    if (!seen) break;
    v = clamp(v, -32768, 32767);
    ((int16_t*)buf)[tokens] = sign * v;                         // s16i
}
```

要点（均为硬观察）：

| 行为 | 指令证据 |
|---|---|
| 跳过空格 `0x20` / 制表符 `0x09` | `0x4200E089`–`0x4200E0A1` |
| 支持 `-`(0x2D) 与 `+`(0x2B) | `0x4200E0AC`–`0x4200E0BF` |
| `v = v*10 + d`（addx4→5v，addx2→10v+d） | `0x4200E110`、`0x4200E11C` |
| 钳位 `-32768` / `32767` | `0x4200E13E`–`0x4200E147`（`l32r 0xFFFF8000` / `0x7FFF`） |
| 负数取反 + `sext 15` | `0x4200E138`–`0x4200E14A` |
| 结果写 `int16` | `0x4200E157`（`s16i`） |

### 9.2 `move(` 主体（入口 `0x4200E024`，长度 396 字节）

```c
void km_move(ctx, reply_arg, _unused, buf, len)
{
    int16_t v[5] = {0};
    int n = parse_ints(buf, len, v);      // 0..5 个值

    if (n < 2) { return; }                // 少于 2 个参数：静默返回（连回执都没有）
    if (n == 2) {
        move_commit(ctx, v[0], v[1], 1);  // -> 0x42010BC4，档位固定 1
    } else if (n == 5) {
        ext_move(ctx, v[0], v[1], v[2], v[3], v[4]);   // -> 0x4200F744
    } else {                              // 3/4 个参数：照常移动，第 3 值当档位
        int mode = v[2]; if (mode < 2) mode = 1;
        move_commit(ctx, v[0], v[1], mode);
    }
    reply();                              // 0x4200E1A4
}
```

> **修正（第 7 轮）**：旧版写“3/4 个参数不动作”，实际是**继续移动**、把第 3 个
> 值当档位（`<2` 时取 1）。补丁版反编译（`excw` 换成 no-op 后）完整展开了这条
> 分支；早期实测只看了“有没有回显”，没观测鼠标是否移动，所以漏了这一点。

调用链 [观察]：

```
0x4200E024  km_move
 ├─(n==2) 0x42010BC4  move_commit(ctx,x,y,mode=1)
 │          ├─ mode < 2 → 0x4200F8E4   （默认档提交）
 │          └─ else     → 0x42010B60 → 0x4200EFEC(x,y,mode,0,0)
 └─(n==5) 0x4200F744  ext_move(ctx,x,y,z,w,v)
            └─ 0x4200EFEC(x, y, z, 1, w, v)     // 第 4 参固定 1 = 扩展模式
```

`FUN_4200EFEC` 是两条路径的汇合点，即最终「把一次相对移动写进提交队列」的函数；`0x4200F8E4` 是默认档包装。

### 9.3 `wheel(`（入口 `0x4200E358`，长度 251 字节）

```c
void km_wheel(ctx, reply_arg, _unused, buf, len)
{
    int8_t delta = 0;
    if (len) {
        skip_spaces();
        sign = (c=='-') ? -1 : +1;
        if (c=='-'||c=='+') idx++;
        v = 0; seen = 0;
        while (digit) { v = v*10 + d; seen = 1; }
        if (seen) {
            v = clamp(v, -32768, 32767);
            delta = (int8_t)(sign * v);      // sext 7 → -128..127
        }
    }
    wheel_submit(ctx, delta);                // 0x42010BEC -> 0x4200F96C
    reply();
}
```

| 行为 | 指令证据 |
|---|---|
| 空串/无数字 → 0 | `0x4200E43E`、`0x4200E449` |
| 只解析 1 个值 | 无逗号循环，`0x4200E3ED` 的 `loop` 只走一遍 |
| 值域压到 int8 | `0x4200E438`（`sext a11,a14,7`） |
| 提交 | `0x4200E449` → `0x42010BEC` → `0x4200F96C` |

| 项 | 结论 | 置信度 |
|---|---|---|
| `move(` 参数个数 | 2 个标准移动；3/4 个按第 3 值当档位（`<2` 取 1）；5 个为扩展模式 | 高（补丁版反编译 + 逐指令核对） |
| `move(` 数值范围 | int16，`-32768..32767` | 高 |
| `move(` 分隔符 | 逗号，允许空格/制表符，允许 `+`/`-` | 高 |
| `wheel(` 数值范围 | int8，`-128..127` | 高 |
| 第 3/4/5 个参数的确切含义 | 静态可确认「第 3 值作档位、`<2` 归 1」与「5 参走扩展提交」，单位与语义需上机验证 | 中 |
| 超出范围时的表现 | `move` 走钳位；`wheel` 先钳 int16 再截 int8（大值会回绕） | 高 |

> **已撤销的旧结论**：早先记载 5 参分支带「第 3 参 1..1024 的校验」，
> 逐指令复核 `0x4200E183`–`0x4200E1A1` 后没有该比较，只有
> `bltui v[2], 2 → mode = 1`。以本节为准。

## 10. 二进制帧路由（补充）

命名剩余函数时发现 UART0 的接收路径不止文本命令，`0x4200DB04` 是一个**首字节路由器** [观察]：

```c
void frame_router(uint8_t *buf, int len)
{
    uint8_t op = *buf++;
    if (op == 0xA2) return;                     // 心跳/忽略
    if (op == 0x2E) { cmd_dispatch(buf, len-1); return; }   // '.' → 文本命令
    if (op == 0xA1) { reply(&0xA1, 1); return; }            // ack
    if (op == 0xA4) { config_load(buf); return; }           // NVS 配置读取
    if (op == 0xA5 && len-1 >= 4) {                        // 写序列号
        SERIAL_SETUP(*(uint32_t*)buf); return;
    }
    frame_echo_hex(op, buf, len-1);             // 未知帧：按 "%02X " 回显
}
```

| 首字节 | 处理 | 证据 |
|---|---|---|
| `0x2E` `.` | 进入文本命令分发 `cmd_dispatch` | `0x4200DB04` 分支 |
| `0xA1` | 回 1 字节 `0xA1`（ack） | 同上 |
| `0xA2` | 直接返回（忽略） | 同上 |
| `0xA4` | `config_load`：读 NVS `storage/config/baud_rate` | `0x420130A4` |
| `0xA5` | 后随 4 字节 → `SERIAL_SETUP(value)`，写序列号 | 同上 |
| 其它 | `frame_echo_hex`：`"%02X "` 十六进制回显 | `0x4200DAD8` |

**推论**：文本帧实际是 `.` 前缀 + `km.xxx`，即完整线上格式为 `.km.left()\r`。未知 opcode 只被回显、不会分发，所以 §2 的 13 个隐藏处理函数仍不受这条路由驱动，它们更可能由片间 UART1 或内部调用触发。
